## Frozen V2 selection

Use the same Open Images V7 CSV bytes and hashes recorded in V1's private manifest. The official validation split remains partitioned into development/calibration using SHA-256(`w61-v1|validation|<image-id>`) first byte <128 versus >=128; official test is the sealed holdout. Remove all 180 V1 IDs before selection. Human face boxes `/m/0dzct`, manual/verified sources, group/depiction/geometry exclusions, and human-verified negatives are unchanged. Classify mutually exclusively in order multiple, lower, small, other single, and negative as in V1.

For each set/stratum, rank candidate IDs by SHA-256(`w61-v2|<set>|<stratum>|<image-id>`) then ID. Inspect at most the first **100 positive** or **200 negative** candidates, strictly in that order. Each candidate is eligible only if (a) official image metadata lists CC BY 2.0/4.0; (b) the original landing page returns HTTP 200 and its ImageObject license and `acquireLicensePage` identify the same photo and same CC BY license; (c) the original image URL returns decodable image bytes <=5 MB; (d) its metadata and pixel SHA-256 are recorded. One retry on connection timeout with 30-second connect/read limits is allowed, with reason and attempt count saved. If any check fails, record candidate ID, URL, response/error and reason, then continue to the next ranked candidate. Select the first **10 eligible** for each positive stratum and **20 eligible** negatives. Never inspect model output during candidate choice. After 10/20 are selected, freeze IDs, boxes, source hashes, page confirmation, pixel hashes, attempt log, selector script hash and manifest SHA **before development inference**. No ID is replaced after this freeze, even for decode/inference failures.

Each acquisition run has one foreground owner/PID and a 15-minute monotonic deadline. The selector checkpoints the ordered candidate log after each attempt; if the deadline arrives, it records `incomplete_deadline`, exits, and resumes from the same ranked next candidate on the next bounded run. A deadline is not a failed corpus result and does not change IDs or quotas. The parent worktree does not own any background fetch process.

Acquisition may fetch a pair of adjacent ranked candidates concurrently. Outcomes are committed in rank order and only the first quota of eligible IDs is selected; the second fetched candidate at a quota boundary is logged but never substituted into the frozen sample. This affects elapsed time only and is fixed before inference.

Development may be used to fix implementation errors, calibration only to choose a cutoff if V1's fixed 0.50 fails and a new preregistration plus fresh holdout is prepared. Under this V2 protocol the cutoff remains 0.50; the holdout is opened exactly once after development/calibration decisions are frozen. No test-set tuning. If the eligible quota or completeness criteria fail in any set, record a corpus gate failure and keep `unknown/review` rather than relaxing thresholds. Holdout images remain unused until its ID/rights/pixel manifest has been frozen without model predictions.

Before any accuracy inference, verify exactly 60 selected IDs per set, all 180 IDs distinct from each other and from V1, and all selected pixel SHA-256 values distinct **across sets**. A duplicate byte hash across development/calibration/holdout is a corpus conflict: stop before inference, preserve the selected sample, and do not substitute another ID silently. Different byte hashes do not rule out resized or otherwise near-duplicate photos; that limitation remains explicit.

V2 still cannot establish blur, skin tone, eye visibility, video motion, tracking, or final MP4 subtitle safety. Those require separate human-adjudicated strata and final-pixel evidence. Open Images independence from WIDER FACE is by dataset source only; individual-image training overlap has not been ruled out.

Pixel orientation follows the Open Images [official image-information field definition](https://storage.googleapis.com/openimages/web/download_v7.html#df-image-information): `Rotation` is the number of degrees to rotate the encoded original **counterclockwise** to match Flickr's intended orientation. OpenCV decoding explicitly ignores EXIF orientation before applying this field once. This is a reproducible mapping rule, not a guarantee that every original still matches the historical annotation.

Before inference, compare each downloaded original's byte length to `OriginalSize` and its base64-encoded binary MD5 to `OriginalMD5` from that same official metadata field. A mismatch is a source-fidelity failure counted against sample completeness and recall, without a replacement. `Rotation=nan` or missing orientation is unknown, not zero; count that frame as failed rather than silently align boxes to an assumed orientation.
