## O que existe

- **Modelo completado, nunca duplicado**: as versões imutáveis hash-verificadas já existiam (`synthetic_presenter_profiles`); esta wave adiciona a tabela de head (`synthetic_presenter_profile_heads`, migration `20260829100000`, com backfill das linhas existentes) com CAS em `currentVersion` e versões estritamente sequenciais, mais os campos opcionais aditivos `pronunciationDictionaryRef`, `visualContinuity` e `restrictions` sob o mesmo `schemaVersion` v1 (entram no corpo hashado só quando presentes — snapshots antigos continuam byte-verificáveis). `db:v2:validate` = 189 tabelas / 967 índices / 750 FKs.
- **Lifecycle versionado**: criar (v1 avança o head), nova versão por merge de changes (replay idempotente ANTES do OCC; `null` limpa campo opcional), ativar/desativar (cada transição É uma versão nova; ativação gated pelo consent embutido válido no instante), anexar prova de consent (artifact existente obrigatório), expirar computado no gate (nunca cron). Registrar uma versão com consent revogado É o ato de revogação; reativação com consent revogado/expirado falha fechada.
- **Policy engine determinístico fail-closed** (`synthetic-presenter-policy/v1`, ADR-144): acumula TODAS as razões, nega operação não classificada (voice-clone/lip-sync ⇒ `OPERATION_UNCLASSIFIED`), snapshot adulterado (`PAYLOAD_TAMPERED`), workspace divergente, uso/mercado/locale fora do escopo consentido, expiry/revocation; com o head presente, a vontade ATUAL do ator prevalece sobre snapshots antigos (`CURRENT_CONSENT_REVOKED`/`CURRENT_VERSION_NOT_ACTIVE`). `assertSyntheticPresenterPolicy` ⇒ `ASSET_RIGHTS_BLOCKED` ANTES de custo, cache, submit, reuse e master; `assertBlockGenerationConsent` delega ao engine com o head.
- **API /v1**: 7 capabilities `apollo.synthetic-presenters.*` (list, get, create-version, activate, deactivate, attach-consent-proof, evaluate-eligibility) com baseRevision + idempotência nas mutações, preflight determinístico de elegibilidade, audits de concorrência/precondição, regras de agent-tool-safety e baseline/parity atualizados deliberadamente (274 capabilities).
- **UI real em `/presenters`** (`SyntheticPresentersManager`): tudo via `/v1` com a sessão de UI (zero Prisma direto, zero rota legada); lista com estados vazio/carregando/erro (erro NUNCA vira lista vazia — `role="alert"` com retry), criação por formulário, detalhe com consent/restrictions/disclosure, ativar/desativar com confirmação proporcional (duplo clique explícito), avaliação de elegibilidade com veredito e razões, histórico completo de versões em tabela acessível.

## Limitações honestas

- Screenshots são evidência efêmera: capturados a cada execução (localmente em `APOLLO_PRESENTER_SHOTS_DIR`), não versionados no repositório; a prova durável são os asserts sobre UI/API/PG.
- Só `tts` e `audio-avatar` têm política classificada; clone/lip-sync são sempre negados até o gate deles existir.
- Vários profiles ativos por workspace são permitidos de propósito (exclusividade é decisão editorial, não de direitos).
- A UI não expõe criação de nova versão arbitrária (voz/dicionário) nem clone de profile; essas mutações existem só via `/v1`.
- O attach de consent proof pela UI exige artifact já existente no workspace; a UI não faz upload de evidência.
