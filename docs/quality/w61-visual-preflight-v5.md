# W61 corpus preregistration v5 — CVDF derivative, Rotation 0

This protocol is written before V5 selection/download and before any face-model inference. V1 failed original rights/acquisition; V2 failed unknown orientation; V3 failed an artificial cross-version exclusion; V4 acquired only 41/60 development cases before repeated original-pixel HTTP 429. Preserve those manifests and the V4 429 defer ledger. Do not retry Flickr 429 or route around it. No detector output has influenced any corpus version.

V5 retains V1's frozen quantitative thresholds and development/calibration/holdout partition. It changes only the encoded image source to the [official Open Images CVDF mirror](https://storage.googleapis.com/openimages/web/download_v7.html), limits eligible metadata to `Rotation=0`, and explicitly reuses IDs and verified original-page HTML from V1–V4. The CVDF JPEG at `https://open-images-dataset.s3.amazonaws.com/{validation|test}/{image-id}.jpg` is a **resampled derivative** (longest side generally 1024), not the original in Open Images `OriginalMD5`/`OriginalSize`: the eight-image preselection spike includes one 640→1024 upscale. Never use original MD5/size to authenticate mirror bytes. Record URL, HTTP status, content length, simple ETag, local MD5/SHA-256, JPEG dimensions and EXIF orientation. Require a simple 32-hex ETag equal to the downloaded bytes' MD5, size <=5 MB, JPEG decode, longest side <=1024, positive dimensions, and EXIF orientation absent or 1. Where original bytes were previously verified and cached, compare the mirror's aspect ratio to those original dimensions within integer resize rounding. For new IDs, the CSV does not include original dimensions; record `aspect_original_unverified` and rely on the official ID mapping, Rotation=0 and neutral EXIF without claiming per-image orientation proof. Reject/record failure without switching image source. Preserve the exact mirror bytes privately; all benchmark cases use that same source, including previously acquired originals.

The mirror does not confer image rights. For each ID require official metadata's CC BY 2.0/4.0 URL **and** the saved or freshly retrieved original landing-page HTML binding that same photo to that exact license; preserve landing URL/final URL, HTML bytes/hash/timestamp, author/attribution, and source metadata. Previously saved HTML is reusable only after its SHA-256, landing URL, and per-photo license are rechecked. A missing, mismatched, or rate-limited landing page is `rights_unconfirmed`, not a negative or a detector failure. Human ground truth remains official validation/test `Human face` boxes (`xclick`/`activemil`, excluding group/depiction/invalid geometry) and explicit human `Confidence=0` image-level negatives. The image-to-box correspondence for new IDs is the official CVDF publication keyed by split/ImageID, not a claim of per-image original-pixel comparison; the eight-case spike provides limited empirical orientation evidence. Mirror pixel changes can affect measured accuracy; describe it as Open Images CVDF-derivative accuracy, not original-pixel accuracy.

The seven source CSV/class-description URLs and SHA-256 remain frozen in V1. `scripts/validation/w61-v5-inventory.py` verifies all source hashes before counting. Validation IDs partition by first SHA-256 byte of `w61-v1|validation|<image-id>` (<128 development, otherwise calibration); official test is sealed holdout. The five mutually exclusive strata and per-set quotas remain multiple 10, lower 10, small 10, other single 10, explicit negative 20. Sort metadata-eligible candidates by SHA-256(`w61-v3|<set>|<stratum>|<image-id>`) ascending then ID. V4's document said `w61-v4` but its executed selector used `w61-v3`; V5 freezes the **executed** ordering to preserve reproducibility and cached candidates. This discrepancy is disclosed before V5 selection and cannot be resolved using model outputs. Examine all lower candidates, at most the first 100 candidates in each other positive stratum and first 200 negatives, as in V4. Acquisition advances in this frozen order only before inference, logs every failed/deferrred ID and never silently replaces a selected case after inference. Limit network concurrency to two, per-request deadline, 5 MB response, 15-minute supervised runs with checkpoint and owner PID. HTTP 429 pauses acquisition for retry of the same ID after server clearance; it is not semantic ineligibility.

## Acquisition implementation revision before any inference

The first V5 selector run ended after five selected and seven attempted development candidates: reading the header of a cached 21 MP **original** for aspect comparison triggered Pillow's decompression-bomb limit. This was unrelated to mirror decode and did not trigger face inference. The checkpoint was preserved unchanged at SHA-256 `37ea7d989294bbaf7bac762cda3c6cdca51fc7e9ed3f3ac3b8dd8b2c744a0250`; its owner PID 36732 was terminal. Before resumption, the selector was amended to use dimensions previously recorded by V2–V4 only after re-verifying exact cached original bytes by SHA-256, OriginalMD5 and OriginalSize. New IDs retain `aspect_original_unverified`. The pre-acquisition freeze is revisioned and preserves the earlier freeze hash; the same ranked plan/IDs, rights rules, mirror source and thresholds remain fixed. No case was replaced using model output.
