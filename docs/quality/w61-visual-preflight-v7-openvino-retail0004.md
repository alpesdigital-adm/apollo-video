# W61 V7 preregistration — one Intel face-detection-retail-0004 FP32 hypothesis

This is a **single diagnostic candidate** after the failed YuNet 640 and 960 development/calibration experiments. It does not alter their reports, human labels, image selection, score thresholds, or sealed 60-image holdout. The hypothesis is that a different SSD face detector described by its publisher as trained with negatives may reject some animal faces mistaken by YuNet. The publisher does not disclose the training-image dataset or the contents of those negatives. WIDER Face AP is a validation result, not proof of the training source or of human-versus-animal discrimination. Its fixed 300×300 input may miss small faces; failure is a valid result.

## Runtime and preprocessing fixed before inference

Run in a private Python 3.14 environment; do not install globally. Use official `openvino==2026.4.0` Windows CPython 3.14 wheel `openvino-2026.4.0-22959-cp314-cp314-win_amd64.whl`, PyPI SHA-256 `eab8a6c71210b2596765e3c9ffbdbe05c1d3b279793806e55162befa898a548f`, size 84,027,824 bytes, package metadata license Apache-2.0. Its CPU plugin requires an AVX2-capable target; verify compatibility before inference. Pin actual Python, OpenVINO package/native DLL, OpenCV/numpy and evaluation-script hashes after isolated installation, then freeze them with this document and the model hashes. Runtime version or binary changes require a new preregistration.

Use a single CPU infer request, two execution threads at most, no GPU/OpenCL, no remote inference. Decode the existing verified CVDF JPEGs in BGR with EXIF orientation ignored; require metadata Rotation=0 and neutral EXIF as in the V5 source audit. Apply the publisher demo's **standard direct resize** to exactly 300×300 using bilinear interpolation, without letterbox, crop, flip, multiscale, augmentation or extra NMS. Feed BGR `NCHW [1,3,300,300]` to the IR. Require output `[1,1,200,7]` entries `[image_id,label,confidence,x_min,y_min,x_max,y_max]`, label 1 for face, finite normalized XYXY, valid bounds, and score **≥0.50** (the Open Model Zoo object-detection demo's default). Reverse the direct resize to normalized source-image XYXY. Any shape/coordinate violation is a failed image, never an empty detection. Compare to unchanged human face boxes using one-to-one matching at IoU **≥0.50**. The model's own postprocessing is part of the pinned IR; do not add a score or NMS sweep.

No threshold search, model substitution or second configuration under this protocol. Do not open holdout after dev/calib without separate review.

The unchanged acceptance targets are: image completeness ≥90% per set; overall human-face recall ≥95%; each qualifying positive stratum recall ≥90%; false-positive rate on explicit negative images ≤10%; CPU median ≤150 ms and p95 ≤500 ms across 30 measurements after three warmups within 30 seconds; incremental peak RSS ≤512 MiB; at most two execution threads. Report total process RSS as well, counts/denominators, all predictions/failures, and calibration diagnostics. If model loading or one fixed run exceeds budget, stop, preserve evidence, and keep `faceSafety=unknown`. These dev/calib sets were already inspected for YuNet failure, so a pass here remains diagnostic and does not replace independent holdout, animal-rich human review, video/eyes/final-pixel validation, integration, deployment or owner acceptance.
