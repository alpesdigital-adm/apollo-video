# ADR-146 — One canonical synthetic cache identity with a persisted decision ledger

Synthetic work has exactly one address. `synthetic-cache-identity.ts` computes it
for both operations the system performs: a TTS key over the exact text, locale,
voice identity and version, model, output format, synthesis configuration hash
and segmentation version; an avatar key over the driving audio checksum, avatar
identity reference, presenter version, model, output format, render
configuration hash, direction and background. The TTS digest is byte-identical
to the `synthetic-block-cache-key/v1` the previous implementation produced —
frozen by a sentinel and asserted against the old function — so no generation
already paid for is orphaned by the centralization.

Three implementations of this question existed before. `splitSyntheticBlocks`
minted a key from an ad-hoc JSON string that nothing persisted was ever
addressed by; `synthetic-block-generation.ts` carried its own copy of the voice
key and hash; and the real path used a third. The invented key is deleted and
the block module re-exports the canonical identity, because two answers to
"is this the same work?" eventually pay twice for the same bytes.

What may never enter an address is enforced by a drift sentinel over the
canonical body: project, project version, block, position, sequence, occurrence,
plan, consent, cost, currency, timeout, retry count, attempt, deadline,
timestamps, workspace, actor and idempotency key. Consent is the important one.
It is eligibility, not identity: baking it into the key would mean that renewing
a consent fabricates a paid regeneration, and that revoking one leaves the old
address reusable. Instead eligibility is re-validated on every lookup, in a
binding order — request and workspace, presenter snapshot, the actor's current
will at the profile head, rights and consent, then the identity, then the
candidate, its criticism, its blob integrity, the output constraints and any
explicit `mustRegenerate` — and only then is a hit declared. Cost is reserved
only after a miss survives that order.

Decisions are durable. `synthetic_cache_decisions` records the outcome (hit,
miss, forced-regenerate or blocked), a canonical reason code and sentence, the
candidate considered, the policy version, the critic hash, the estimated saving
and the cost actually avoided, addressed by a decision hash so a replay never
doubles the economics. The subject is stored as a domain-separated hash, never
as text: the ledger must be auditable without holding the script, the consent
evidence or a provider secret, and a forbidden-field sentinel enforces it.

Avoided cost is evidence rather than arithmetic. It is read from the provider
job estimate that actually paid for the reused candidate, following the
source-generation chain to the row that carries the job; when no estimate
exists the reuse fails closed instead of claiming a saving nobody can prove.
Summaries report amounts per currency for the same reason — summing minor units
across currencies would invent an exchange rate.

Invalidation is precise and never destructive. A change to the generated bytes
produces a new address and therefore a legitimate miss; a change in eligibility
blocks reuse while the artifact stays exactly where it is; an editorial or
positional change keeps the hit, because position was never part of identity;
an expired or corrupted candidate becomes ineligible with its bytes preserved;
and an explicit `mustRegenerate` is an audited, policy-restricted decision that
appears in the ledger with its reason. Nothing is deleted to invalidate a cache.
