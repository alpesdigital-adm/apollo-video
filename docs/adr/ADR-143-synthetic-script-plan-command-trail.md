# ADR-143 — Synthetic script plan command trail

Block plans version themselves through their own append-only command trail instead of registering new types in the editorial `EDIT_COMMAND_POLICIES` registry. Each command and the plan version it produced are the same immutable row: `synthetic_script_plan_versions` records commandType, `baseVersionId` (parent), the resulting sequence, a canonical impact (created, reused and retired blocks, cache decisions with persisted reasons, render semantics and `commandImpactHash`) and `planVersionHash`. Optimistic concurrency compare-and-swaps the plan head's `currentVersionId`, exactly like the project head, and every request must carry both the exact `baseVersionId` and its immutable `baseHash`; either being stale fails closed with `VERSION_CONFLICT`. Replay is idempotent per actor, fingerprint-checked.

The editorial registry stays untouched because block work is audio-domain and pre-render: script mutations record `deferred-to-compile` render semantics and only `compile-audio` — itself a plan command with `no-render` semantics — materializes a consolidated `SyntheticAudioMaster`. Binding every script tweak to a full ProjectVersion snapshot would force render-implicated versions for changes that cannot touch the timeline; instead each plan version records the `projectVersionId` that was current when its command ran, and provider jobs keep enforcing the current project version at enqueue time.

Block identity is immutable and never encodes position: order lives only in the version's `blockSequence`, reordering touches no identity, editing retires the block in favour of a replacement that records its lineage, and repeated identical sentences stay distinct ordered occurrences. Segmentation is deterministic and versioned (`synthetic-script-segmentation/v1`); the algorithm version participates in every block cache key so changing segmentation can never silently reuse stale audio.
