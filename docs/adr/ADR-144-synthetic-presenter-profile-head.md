# ADR-144 — Synthetic presenter profile head and fail-closed policy engine

Synthetic presenter profiles gained a head table (`synthetic_presenter_profile_heads`) alongside the pre-existing immutable version rows: the head compare-and-swaps `currentVersion` under strictly sequential version numbers, and the row it points to is the actor's most recent will. Every lifecycle transition — new consent proof, restriction change, activation, deactivation — is the registration of a NEW hash-verified version that advances the head; nothing is ever mutated in place. Registering a version whose consent is revoked IS the act of revocation: there is no separate revocation flag to drift from the audited snapshot, and reactivation is gated on the consent embedded in the version being valid at evaluation time, so a revoked or expired consent makes `activation` fail closed.

Policy decisions are centralized in the deterministic engine `synthetic-presenter-policy/v1` (`evaluateSyntheticPresenterPolicy`). It always accumulates every applicable reason instead of short-circuiting, and it fails closed on anything it cannot positively verify: tampered snapshot hashes, unclassified operations (voice-clone and lip-sync have no classified policy yet and are always denied with `OPERATION_UNCLASSIFIED`), workspace mismatches. When the caller can supply the profile head, the engine also judges the snapshot against the actor's CURRENT will — an old still-consented snapshot is denied with `CURRENT_CONSENT_REVOKED`/`CURRENT_VERSION_NOT_ACTIVE` when the actor has since revoked or deactivated — so cached snapshots can never outlive the actor's decision. `assertSyntheticPresenterPolicy` maps denial to `ASSET_RIGHTS_BLOCKED` and runs BEFORE any cost reservation, cache hit, provider submit, artifact reuse or master consolidation; block generation (`assertBlockGenerationConsent`) delegates to it with the head attached.

Consent expiry is computed at the gate from the version's `expiresAt`, never materialized by a cron: an "active" profile with expired consent is blocked the moment it is evaluated, with zero scheduled mutation. Multiple active profiles per workspace remain allowed — exclusivity is an editorial choice, not a rights property. The optional profile fields added in this wave (`pronunciationDictionaryRef`, `visualContinuity`, `restrictions`) are additive under the same `schemaVersion` v1 and join the hashed body only when present, keeping every previously persisted snapshot byte-verifiable.
