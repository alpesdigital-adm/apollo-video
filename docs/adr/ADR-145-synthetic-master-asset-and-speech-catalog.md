# ADR-145 — Synthetic master assets and their speech catalog

A generated performance is sealed as an immutable, content-addressed
`synthetic-master-asset/v1` instead of being left as a pile of provider result
artifacts. The master binds the originating project version, the logical
presenter and the exact snapshot the bytes were generated from, the consent and
authorization hashes, the rights snapshot, the provider job with its four
ingested roles (provider-original, normalized-video, final-audio, alignment),
the script and its hash, the sanitized adapter/model/config hash, observed cost
and latency, the approving critic evidence and the block generation lineage.
Composition — captions, LUTs, B-roll, overlays, output formats — has no field in
the master, so an editorial change can never invalidate generated bytes
(spec 06 §13). Audio governs the timeline: `durationMs` must equal the measured
audio duration and a video track drifting past one 30fps frame is rejected as a
different performance rather than stored as an approximation.

The required roles are the ones the pipeline actually produces —
`provider-original`, `final-audio` and `alignment`, mirroring the three roles the
provider result ledger admits. `normalized-video` stays modelled but optional:
no stage normalizes provider video today, and pointing that role at the
untouched original bytes would assert a normalization that never ran. The first
modelling of this wave required all four roles and was corrected when the
end-to-end journey proved, against the ledger's CHECK constraint, that nothing
writes the fourth.

Promotion is a gate, not a copy. Nothing is published until the job is terminal
and approved with a critic result, every ingested role exists in the provider
result ledger, each artifact is catalogued and available with checksum and byte
size matching the ledger, storage actually holds those bytes, the presenter
snapshot is intact and still allowed by the policy engine, asset rights clear
every artifact for the requested use and market, and the measured durations
agree. The repository re-checks the presenter hash and the job's critic result
inside the sealing transaction, so a snapshot or approval that moves between
validation and commit is a `VERSION_CONFLICT` instead of a silently published
master. Identity is the content address: `(workspaceId, masterHash)` and
`(workspaceId, providerJobId)` are both unique, so the same performance is never
sealed twice and one approved job yields exactly one master.

Reusable sentences are catalogued in a dedicated `synthetic_speech_segments`
table rather than in `speech_segments`. That existing catalog describes speech
extracted from ingested real media and requires a catalog run, a media
transcript and an extracted complete-thought score; a synthetic sentence has
none of them, so reusing the table would mean fabricating a transcript and a
catalog run that never happened — false provenance in the exact place where
provenance is the product. The attribute ontology is deliberately identical
(exact and normalized text, half-open range, emotion, wardrobe, setting,
framing) so both catalogs answer the same reuse questions, and emotion stays
null because no measured source exists yet. Cataloguing is a pure function of
the sealed master: boundaries are the F3.005 block boundaries, never
re-segmented, and ranges are matched word by word against the persisted
alignment. A block whose words are absent, out of order or overlapping fails
closed instead of inventing a range, and the silence between sentences remains a
real gap rather than being absorbed to make the timeline look contiguous.

The in-memory `SyntheticMasterAsset`, `catalogSyntheticMaster` and
`reuseSyntheticBlock` that lived in `synthetic-production.ts` are removed. They
were a second, unpersisted implementation of this decision with zero call sites
in `src/`, exercised only by unit asserts; keeping them would have left two
answers to the same question, which is exactly what the F3.007 gate forbids.
